# MultithreadedSorting 

개인 프로젝트  |  네 가지 정렬의 동시 실행과 시각화 

## **1 프로젝트 소개** 

Bubble Sort, Selection Sort, Quick Sort, Merge Sort 를 직접 구현하고 각각 별도 스레드에서 실행하는 C++ 시각화 프로젝트입니다. 같은 입력 배열의 복사본을 각 알고리즘에 전달하고 네 개 패널에 정렬 중간 상태를 표시하여 데이터가 정리되는 방식의 차이를 관찰할 수 있도록 했습니다. 

병렬화 단위는 알고리즘별 실행입니다. 하나의 정렬 작업을 여러 워커로 나누는 병렬 정렬 구현이 아니라 네 알고리즘을 동시에 관찰하는 구성입니다. 

## **2 기술 스택** 

|**구분**|**사용 기술**|
|---|---|
|언어 및 빌드|C++20 / CMake|
|스레드 및 공유 상태|std::thread / std::mutex / std::atomic|
|UI 및 렌더링|Dear ImGui / DirectX 11 / Win32|
|입력 생성 및 시간|mt19937 / uniform_int_distribution / std::chrono|



## **3 주요 기능** 

### **같은 데이터로 네 알고리즘 실행** 

프로그램 시작 시 1~100 범위의 정수 100 개를 생성합니다. Start 를 누르면 원본의 복사본을 각각 정렬합니다. 

### **막대 그래프와 상태 표시** 

각 패널은 배열 값을 막대 높이로 표시하고 Ready, Running, Finished 상태를 보여줍니다. 완료 후에는 해당 정렬 호출의 경과 시간을 초 단위로 표시합니다. 

### **UI 와 정렬 스레드의 분리** 

정렬은 네 작업 스레드에서 수행하고 메시지 처리와 ImGui 렌더링은 메인 스레드에서 진행합니다. 중간 배열은 동기화된 Visualizer 를 통해 화면에 전달합니다. 

## **4 핵심 설계와 구현** 

### **공통 정렬 인터페이스와 단계 콜백** 

SortAlgorithm 에 Sort, GetName 과 StepCallback 을 정의합니다. 알고리즘은 내부 데이터 변경 시 NotifyStep 으로 배열을 전달하므로, 정렬 구현과 화면 표시 코드를 분리할 수 있습니다. 

|**알고리즘**|**구현 특징**|**시각화 갱신 시점**|
|---|---|---|
|Bubble Sort|인접 비교·교환 / 교환 없는 패스에서 종료|교환 발생 시|
|Selection Sort|남은 구간의 최솟값을 찾아 배치|실제 교환 시|
|Quick Sort|중앙 값 피벗 / 양끝 포인터 분할|분할 중 교환 시|
|Merge Sort|재귀 분할 / 임시 배열을 사용한 병합|원본 배열에 값 기록 시|



### **mutex 로 보호하는 화면용 스냅샷** 

Visualizer::Update 는 mutex 를 잡고 배열을 복사합니다. 메인 스레드의 GetData 도 같은 mutex 로 보호한 복사본을 반환합니다. UI 는 반환된 복사본을 그리므로 작업 스레드가 수정 중인 배열을 직접 읽지 않습니다. 

### **원자적 상태와 스레드 수명 관리** 

진행 여부, 완료 개수, 알고리즘별 완료 상태와 측정 시간을 atomic 으로 공유합니다. 재실행 전 이전 스레드를 join 하고 중단 플래그와 상태를 초기화합니다. 창 종료 또는 Q 입력 시 중단을 요청하고 스레드 합류 후 렌더링 자원을 해제합니다. 

### **관찰 속도를 위한 콜백 지연** 

각 단계 콜백은 스냅샷을 갱신한 뒤 1ms sleep 을 요청합니다. 알고리즘별 콜백 호출 횟수가 다르기 때문에 화면의 완료 시간은 정렬 연산 외에도 복사, 동기화, 지연과 스케줄링 영향을 포함합니다. 

ThreadManager 에는 별도 동시 실행·결과 수집 코드가 존재하지만 현재 GUI 실행 경로는 main.cpp 에서 네 스레드를 직접 관리합니다.
